CHANGE 1 — supabase-py version bump (fixes /health outage)

THE BUG
After yesterday's Supabase key rotation to sb_secret_* format,
Railway's call_handler started failing /health with:
  supabase._sync.client.SupabaseException: Invalid API key
  File "supabase/_sync/client.py", line 64

Root cause: supabase-py v2.10.0 has a hardcoded JWT regex check that
requires at least one dot in the key. sb_secret_* keys have no dots →
regex fails → exception fires before any HTTP request.

VERIFIED FIX
Live-tested across versions in clean venvs:
  v2.10.0   rejects sb_secret_   ← what Railway currently runs
  v2.15.3   rejects sb_secret_   ← last version with the bug
  v2.16.0   accepts sb_secret_   ← FIRST version with the fix

v2.16.0 chosen — minimum-viable bump.

FILES CHANGED
  Dockerfile.call_handler  line 11   supabase==2.10.0 → 2.16.0
  requirements.txt         line 10   supabase==2.10.0 → 2.16.0
  requirements.call_handler.txt  line 16   supabase==2.10.0 → 2.16.0

CHANGE 3 — Deepgram STT opts out of Model Improvement Program

THE PRIVACY ISSUE
Default Deepgram behavior retains a fraction of customer audio for
model training under their MIP program. For a voice receptionist
handling private customer conversations, this is unacceptable.

REFERENCE
https://developers.deepgram.com/docs/the-deepgram-model-improvement-partnership-program

  "Add mip_opt_out=true ... Data from opted-out requests is retained
   only for the duration necessary to process the request."

VERIFIED PLUGIN SUPPORT
livekit-agents[deepgram]==1.5.1 (our pinned version) accepts mip_opt_out
as a constructor kwarg. Verified via inspect.signature() in a clean
venv install — `mip_opt_out: bool = False` is in deepgram_plugin.STT.__init__.

FILE CHANGED
  aria_agent.py  Deepgram STT init (around line 3777)

  Added:
    mip_opt_out=True,

  Updated log line includes "mip_opt_out=true" so we can verify in
  Railway logs that the new build is live.

NO OTHER CHANGES NEEDED
  - TTS uses openai.TTS, not Deepgram — unaffected
  - call_handler.py does not use Deepgram (grep confirmed)
  - Only the LiveKit video-agent path (aria_agent.py) uses Deepgram
