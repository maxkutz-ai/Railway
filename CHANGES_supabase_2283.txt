BREAKING CHANGES BETWEEN 2.16.0 AND 2.28.3 — IMPACT ANALYSIS

1. supabase_auth SyncClient classes removed (introduced ~2.23.x)
   Replaced with plain httpx.Client.
   IMPACT: NONE. Our Railway code does not use sb.auth.* anywhere. Verified
   via grep across call_handler.py, aria_agent.py, aria_webhook.py.

2. supabase_functions SyncClient classes removed (introduced ~2.23.x)
   IMPACT: NONE. Our code does not use sb.functions.* anywhere.

3. gotrue package renamed to supabase-auth
   IMPACT: TRANSPARENT. We don't import gotrue directly. The supabase
   metapackage handles the rename internally.

4. Storage signed URL behavior change (auth: return auth_response instead
   of dict from exchange_code_for_session)
   IMPACT: NONE. Our code does not use storage signed URLs from Railway.

5. Storage adds upsert option for signed bucket
   IMPACT: NONE. Additive feature, doesn't change existing behavior.

API SURFACE WE USE — UNCHANGED:
  sb.from_(table)        ← still SyncSelectRequestBuilder etc.
  sb.table(table)         ← still works (alias for from_)
  sb.rpc(name, params)    ← still SyncRPCFilterRequestBuilder
  .select() .eq() .order() .limit() .maybe_single()
  .insert() .upsert(on_conflict=) .delete()
  .execute()

All verified via live test against fresh 2.28.3 install — see VERIFICATION
section below.
